## 2. Найденные баги (результат глубокого аудита кода)

### 🔴 CRITICAL (Критические — риск потери данных / краш)

#### C1. LWW синхронизация: потеря изменений при конфликте двух устройств

- **Серьёзность:** 🔴 Критический
- **Компонент:** `lib/providers/diary_sync_engine.dart`, sync() ~lines 260-275
- **Описание:** После pull/LWW merge, `localByUuidFinal` пересоздаётся из БД. Если Device A редактирует запись с `updatedAt=T1`, а Device B — с `updatedAt=T2>T1`, то при синке Device A LWW перезапишет его `updatedAt` на T2. Затем `toPush` сравнивает `T2.isAfter(T2)` = false → изменения Device A теряются.
- **Код:** `diary_sync_engine.dart` — цикл `toPush` после LWW merge
- **Воспроизведение:**
  1. Создать запись на Device A с `updatedAt=T1`
  2. Редактировать на Device B с `updatedAt=T2>T1`
  3. Device B синхронизируется (сервер получает T2)
  4. Device A синхронизируется — LWW перезаписывает A's updatedAt на T2
  5. Изменения Device A НЕ пушатся (`T2.isAfter(T2)` = false)
- **Влияние:** Потеря изменений пользователя при одновременном редактировании на двух устройствах
- **Рекомендация:** Добавить локальный «dirty flag» per entry для отличия «изменено локально, не синхронизировано» от «уже синхронизировано». Альтернатива — vector clocks или поле «last modified by device».

#### C2. AppDatabase.insertDiaryEntry: ConflictAlgorithm.ignore — тихая потеря данных

- **Серьёзность:** 🔴 Критический
- **Компонент:** `lib/db/app_database.dart`, insertDiaryEntry ~line 99
- **Описание:** `ConflictAlgorithm.ignore` тихо отбрасывает дублирующую вставку по UUID без ошибки. Возвращаемое значение 0 не проверяется вызывающим кодом.
- **Код:** `app_database.dart` line 99: `conflictAlgorithm: ConflictAlgorithm.ignore`
- **Воспроизведение:** Вставить две записи с одинаковым UUID.
- **Влияние:** Вторая запись тихо теряется. При синхронизации это может привести к потере данных.
- **Рекомендация:** Использовать `ConflictAlgorithm.replace` или `ConflictAlgorithm.rollback`, проверять возвращаемое значение.

#### C3. HuntingRecord даты: потенциальный краш при невалидной дате

- **Серьёзность:** 🔴 Критический (потенциальный)
- **Компонент:** `lib/data/regions_repository.dart`, getRegions ~lines 52-57
- **Описание:** `DateTime(year + 1, 2, 30)` выбросит исключение для не-високосного года. Текущие данные не触及 это, но паттерн хрупкий.
- **Код:** `regions_repository.dart` line 53: `DateTime(year + 1, s.closeMonth, s.closeDay)`
- **Влияние:** Краш при создании региона с невалидной датой (например, 30 февраля).
- **Рекомендация:** Валидировать диапазоны дат при конструировании SeasonPeriod.

### 🟠 HIGH (Высокий — сломана ключевая функция)

#### H1. DiaryProvider._uploadEntry: _lastPostUploadSync не сбрасывается при sign-in

- **Серьёзность:** 🟠 Высокий
- **Компонент:** `lib/providers/diary_provider.dart`, _uploadEntry ~lines 260-275

- **Код:** `diary_provider.dart` line 260: `final last = _lastPostUploadSync;`
- **Влияние:** Задержка синхронизации после входа.
- **Рекомендация:** Сбрасывать `_lastPostUploadSync` при sign-in или в syncWithServer.

#### H2. DocumentProvider._uploadDocument: N+1 SELECT-then-INSERT/UPDATE

- **Серьёзность:** 🟠 Высокий
- **Компонент:** `lib/providers/document_provider.dart`, _uploadDocument ~lines 196-220
- **Описание:** Comment говорит «onConflict: 'user_id, title'», но код делает SELECT → INSERT/UPDATE. Race condition при параллельных устройствах.
- **Код:** `document_provider.dart` lines 196-220
- **Воспроизведение:** Два устройства обновляют один документ одновременно.
- **Влияние:** Race condition, potential duplicate inserts или update failures.
- **Рекомендация:** Использовать Supabase `.upsert()` с `onConflict: 'user_id, title'` как в комментарии.

#### H3. DiaryProvider._enqueueUpload: _lastError перезаписывается upload-ошибкой

- **Серьёзность:** 🟠 Высокий
- **Компонент:** `lib/providers/diary_provider.dart`, _enqueueUpload ~lines 62-67
- **Описание:** `_lastError` используется и sync, и upload. Upload-ошибка перезаписывает sync-ошибку.
- **Код:** `diary_provider.dart` line 65: `_lastError = _lastUploadError;`
- **Влияние:** Пользователь видит неправильное сообщение об ошибке.
- **Рекомендация:** Раздельные поля ошибок для sync и upload.

#### H4. DocumentProvider: auth state subscription не dispose

- **Код:** `document_provider.dart` line 54-56
- **Влияние:** Memory leak, potential use-after-dispose.
- **Рекомендация:** Сохранить `StreamSubscription` и отменить в dispose().

#### H5. DiaryScreen: null id crash при удалении из detail screen

- **Серьёзность:** 🟠 Высокий

#### H6. AnalyticsService.calculateTrend: некорректный расчёт в январе-феврале
