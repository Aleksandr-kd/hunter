## 2. Найденные баги

### БАГ #1 (ИСПРАВЛЕН): Смена фото в существующей записи не синхронизируется

**Серьёзность:** 🔴 Критический → ✅ Исправлен
**Компонент:** `lib/providers/diary_provider.dart`, `lib/providers/diary_sync_engine.dart`, `lib/models/diary_entry.dart`

**Исправление:**
1. Добавлен метод `copyWith()` в `DiaryEntry` для создания копии с обновлённым `photoUrl`
2. `_pushWithPhoto()` в `DiarySyncEngine` теперь обновляет `entry.photoUrl` через `copyWith` перед отправкой на сервер
3. `_uploadEntry()` в обоих файлах теперь использует `entry.photoUrl` который уже содержит новый URL из `_pushWithPhoto`
4. Удалён дублирующий код вычисления `resolvedPhotoUrl` из старого URL

**Результат:** При смене фото новый URL корректно записывается в БД и синхронизируется между устройствами.

---

### БАГ #2 (НОВЫЙ, СРЕДНИЙ): Старые фото не удаляются из storage

**Серьёзность:** 🟡 Средний
**Описание:** При замене фото старый файл остаётся в bucket `diary-photos`.

---

### БАГ #3 (НОВЫЙ, НИЗКИЙ): Дублирование логики `_uploadEntry`

**Серьёзность:** 🟢 Низкий
**Описание:** `_uploadEntry()` продублирован в `DiaryProvider` и `DiarySyncEngine`.

---

### БАГ #4 (ИЗ ПРОШЛОГО, ✅ ИСПРАВЛЕН): photoUrl не затирается при правке без смены фото

### БАГ #5 (ИЗ ПРОШЛОГО, ✅ ИСПРАВЛЕН): «воскрешение» удалённой записи
