### Стратегия монетизации: бесплатный период → подписки (когда появится ИП)

> ⚠️ **Контекст:** сейчас у автора нет ИП, поэтому монетизация не подключается.
> Приложение публикуется бесплатно, всем пользователям открыты **все** функции.
> Позже, когда появится ИП, включаются подписки. **Необходимо сохранить
> «грандфазеринг» (grandfathered)**: пользователям, установившим приложение до даты
> перелома (`T`), навсегда остаются те функции, что они видели в бесплатный период.
> Новым пользователям — по подписке. Это снижает негатив и отвалы.

**Выбрать дату перелома (T):**
- [ ] Зафиксировать дату `T` (момент первого релиза с включёнными подписками)
- [ ] Добавить в `profiles` (или в `subscriptions`) поле даты создания аккаунта / установки, чтобы отличать «до `T`» и «после `T`»

**Грандфазеринг (один раз, на стороне бэкенда Supabase):**
- [ ] Для всех пользователей, зарегистрированных до `T`, проставить в таблице `subscriptions` `/ profiles` `tier = 'max'` (или `grandfathered = true`) — **раз и навсегда**
- [ ] Убедиться, что `expires_at` для grandfathered не ставится (или ставится на 2030+), чтобы логика `AuthProvider.loadSubscription()` не сбрасывала их в `none` по просрочке
- [ ] Новым пользователям (после `T`) — `tier = 'none'`, обычные лимиты

**Код (клиент) — почти не меняется, т.к. гейтинг уже заложен:**
- [ ] Уже есть: `AuthProvider.loadSubscription()` читает `tier` из Supabase и применяет `isPremium` / `isMax`, лимиты дневника, тёмную тему, экспорт
- [ ] Для grandfathered `tier='max'` — приложение автоматически даст все функции без подписки
- [ ] Для новых `tier='none'` — включить кнопки подписки (см. «Интеграция RuStore SDK» ниже)

**Проверки перед выпуском обновления с подписками:**
- [ ] Старый пользователь (до `T`): видит все функции, кнопки «Подключить» скрыты/неактивны
- [ ] Новый пользователь (после `T`): видит лимиты и кнопки подписки
- [ ] `flutter analyze` и `flutter test` — без ошибок
- [ ] Обновление выкатывается как обычный релиз в RuStore (без удаления данных)
